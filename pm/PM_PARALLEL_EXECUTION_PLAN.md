# Mystery Time PM Parallel Execution Plan

## 1. 문서 목적

이 문서는 `Codex 계정 3개`를 각각 독립적인 AI 개발자로 운용하기 위한 PM 기준 실행 계획서다.

목표는 다음 3가지다.

1. `한 명의 사용자`가 자연어/의사코드로 지시한다.
2. `3개의 AI 개발자`가 서로 충돌하지 않게 병렬 작업한다.
3. 최신 기획안 기준으로 `개인 점수 / 개인 정답 성공 구조`를 가진 게임을 단계적으로 완성한다.

---

## 2. 현재 제품 해석

이번 구현의 핵심 해석은 아래와 같다.

1. 게임은 여전히 `3팀 협력 구조`다.
2. 하지만 점수 집계와 최종 승패는 `개인 기준`이다.
3. 정답 성공도 `개인 기준`이며, 맞힌 플레이어만 해당 스테이지에서 격리된다.
4. 스테이지는 `2명의 개인 플레이어가 정답 성공`하면 종료된다.
5. 질문방은 `서버 대기열 기반 선입선출` 구조로 운영한다.
6. 1:1 채팅은 `전화형 요청-선택-수락` 구조로 운영한다.
7. 팀은 협력과 심리전, 팀 채팅, 스테이지별 조합 변경을 위한 구조로 남는다.
8. 비로그인 사용자는 `랜덤 닉네임`으로 입장하고 닉네임을 수정할 수 없다.
9. 로그인 사용자는 자체 계정으로 입장하고 닉네임과 전적을 관리한다.
10. 방은 `공개방`, `비밀방`, `연습모드`를 지원한다.
11. 방 목록, 제목 검색, 비밀방 비밀번호 입장 흐름이 필요하다.
12. 룰북은 `메인 / 대기방 / 게임중` 3곳에서 항상 모달로 열 수 있어야 한다.

기획안의 세부 문구가 충돌하면 [SHARED_CONTRACTS.md](/home/yusin/mysteryGame/app/pm/SHARED_CONTRACTS.md)를 구현 기준으로 따른다.

### 2.1 현재 라운드 포커스

- Agent 1은 비로그인 랜덤 닉네임, 자체 로그인, 방 모드/비밀번호/연습모드 제약을 서버 계약으로 고정한다.
- Agent 2는 메인 페이지, 대기방, 게임중 화면에서 룰북 모달과 방 목록/검색/설정 UX를 정리한다.
- Agent 3은 로그인/비로그인, 방 타입, 비밀번호, 룰북, 1:1 채팅과 질문방 상태 문구를 정리한다.

## 5. 병렬 작업 원칙

### 5.1 소유권 원칙

- Agent 1은 `DB`, `서버`, `상태`, `실시간`, `점수`를 소유한다.
- Agent 2는 `플레이어 경험`을 소유한다.
- Agent 3은 `AI`, `콘텐츠`, `운영도구`를 소유한다.

서로의 소유 영역을 직접 수정하지 않는 것이 기본 규칙이다.

### 5.2 계약 우선 원칙

공통 계약은 아래 항목을 먼저 고정하고 구현한다.

- 로그인 / 비로그인 입장 모델
- 방 모드 / 비밀번호 / 연습모드 제약
- 방 목록 / 검색 / 필터 기준
- 룰북 모달 제공 위치
- 개인 점수 구조
- 개인 정답 성공 처리
- 조사실 규칙
- 조사실 대기열 규칙
- 질문/정답 AI 응답 형식
- 공개/비공개 정보 경계
- 1:1 채팅 요청/선택/수락/거절/만료 규칙

### 5.3 보고 원칙

각 Codex 계정은 작업 종료 시 아래 형식으로 보고한다.

1. 변경 파일
2. 구현/설계 내용
3. 테스트/검증
4. 리스크
5. 다음 에이전트 handoff

단, `보고 완료`로 인정되는 조건은 아래 2개를 동시에 만족하는 경우뿐이다.

1. [AGENT_COMMAND_PROTOCOL.md](/home/yusin/mysteryGame/app/pm/AGENT_COMMAND_PROTOCOL.md)의 보고 형식을 지킨다.
2. 마지막 줄이 해당 에이전트의 완료 신호로 끝난다.

### 5.4 PM 관제 원칙

- PM은 모든 작업에 `TASK_ID`를 부여한다.
- 각 에이전트에는 동시에 `활성 작업 1개`만 준다.
- PM은 `마지막 줄 신호`로 완료/보류/검토요청을 판정한다.
- handoff가 없으면 다음 작업 연결이 불가능하므로 완료로 보지 않는다.

## 8. PM 체크포인트

PM은 아래 질문으로 각 단계 완료 여부를 판단한다.

1. 점수와 정답 성공이 정말 `개인 기준`으로 일관되게 설계됐는가
2. 팀은 협력 구조로만 남고 점수 원본이 되지 않는가
3. 조사실 비공개 규칙이 서버와 UI 모두에서 지켜지는가
4. 조사실이 클릭 경쟁이 아니라 대기열 순서대로 동작하는가
5. 1:1 채팅이 busy / 선택 / 수락 / 거절 / 만료 규칙대로 동작하는가
6. 비로그인 사용자가 랜덤 닉네임으로만 입장하고 수정하지 못하는가
7. 로그인 사용자가 닉네임과 전적을 정상적으로 보는가
8. 공개방 / 비밀방 / 연습모드 제약이 서버와 UI에서 일치하는가
9. 메인 / 대기방 / 게임중 모두 룰북 모달을 열 수 있는가
10. 다른 플레이어 점수가 스테이지 중 노출되지 않는가
11. 정답 성공 플레이어만 격리되는가
12. 에이전트 간 handoff가 실제 다음 작업 입력으로 재사용 가능한가
