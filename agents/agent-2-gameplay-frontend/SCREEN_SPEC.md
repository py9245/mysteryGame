# Frontend Screen Spec

## 1. 목적

이 문서는 Agent 2가 구현해야 하는 `frontend-owned` 화면과 상태 경계를 정의한다.

핵심 기준은 다음과 같다.

- 플레이어가 `무엇을 해야 하는지` 화면만 보고 이해할 수 있어야 한다.
- 스테이지 중에는 `자기 정보만 우선 노출`한다.
- 다른 플레이어의 점수, 질문, 정답 시도, 비공개 채팅은 노출하지 않는다.
- 정답 성공 후에는 해당 플레이어를 `관전 상태`로 전환한다.

## 2. 공통 UI 상태

- `lobby_waiting`
- `ready_confirmed`
- `team_assigned`
- `stage_briefing`
- `stage_playing`
- `investigation_active`
- `solved_spectator`
- `stage_results`
- `game_results`

이 상태들은 서버 상태를 그대로 복사하는 값이 아니라, 화면 렌더링을 위한 최소 표현이다.

## 3. 화면별 스캐폴드

### 3.1 대기실

- 목적: 입장 확인, 닉네임 확인, 준비 상태 확인
- 보여줄 것: 방 코드, 참가자 목록, 내 준비 상태, 준비완료 버튼, 연결 상태
- 숨길 것: 다른 플레이어 점수, 사건 진실, 질문/정답 기록
- UI 기준: 아직 게임이 시작되지 않았다는 것을 명확히 보여준다

### 3.2 준비완료

- 목적: 플레이어가 시작 가능 상태임을 표시
- 보여줄 것: 내 준비 상태, 팀 배정 대기 문구, 준비 해제 가능 여부
- 숨길 것: 아직 배정되지 않은 팀 정보의 내부 규칙

### 3.3 팀 배정

- 목적: 이번 스테이지에서의 팀 슬롯과 개인 배치를 보여준다
- 보여줄 것: 내 팀, 같은 팀 플레이어, 다른 팀 슬롯, 스테이지별 재배정 안내
- 숨길 것: 다른 팀의 비공개 행동, 점수 합산 로직, 내부 배정 이유

### 3.4 메인 게임 화면

- 목적: 사건을 읽고 게임 흐름을 따라가게 한다
- 보여줄 것: 사건 제목, 사건 설명, 이미지, 남은 시간, 내 점수, 공개 힌트, 채팅 영역, 조사실 진입 버튼
- 숨길 것: 다른 플레이어의 실시간 점수, 다른 팀 질문/정답, 정답 기준, 필수 키워드

### 3.5 조사실

- 목적: 제한된 시간 안에 질문 또는 정답 시도를 하게 한다
- 보여줄 것: 조사실 점유 상태, 남은 입장 시간, 남은 질문 횟수, 남은 정답 시도 횟수, 현재 질문 결과
- 숨길 것: 타 플레이어가 지금 조사실 안에서 무엇을 하는지, 질문 판정 내부 사유의 상세 원문, 정답 판정 기준

### 3.6 정답 성공 후 관전 화면

- 목적: 정답 성공한 플레이어에게 읽기 전용 관전 상태를 제공한다
- 보여줄 것: `정답 성공` 배지, 스테이지 잔여 흐름, 공개 진행 로그, 팀 상태, 내 개인 점수 변화
- 숨길 것: 다시 입력할 수 있는 질문/정답 UI, 타 플레이어의 비공개 행동, 다른 플레이어 개인 점수

### 3.7 결과 화면

- 목적: 게임 종료 후 개인 성과와 전체 순위를 정리한다
- 보여줄 것: 최종 개인 점수, 스테이지별 점수 요약, 정답 성공 순서, 공개 가능한 정답 설명, 전체 순위
- 숨길 것: AI 내부 reasoning, 필수 키워드 전체 목록, 비공개 채팅 내용

## 4. 개인 점수 노출 규칙

- 스테이지 중에는 `본인 점수`만 노출한다.
- 점수 변화는 `내가 방금 받은 delta` 형태로는 보여줄 수 있지만, 타인의 상세 이벤트는 보여주지 않는다.
- 게임 종료 후에는 전체 누적 개인 순위를 공개할 수 있다.
- 개인 점수 카드와 전체 순위 카드는 같은 컴포넌트가 아니라 별도 컴포넌트로 분리한다.

## 5. 비공개 정보 차단 규칙

- 다른 플레이어의 질문 내용은 보여주지 않는다.
- 다른 플레이어의 정답 시도 내용은 보여주지 않는다.
- 오답 여부는 공개하지 않는다.
- AI 판정 근거의 내부 텍스트는 공개하지 않는다.
- 1:1 채팅의 상대 정보는 비참여자에게 노출하지 않는다.
- 다른 플레이어의 실시간 점수와 개인 누적 합계는 스테이지 중 노출하지 않는다.

## 6. 화면 상태 전이

- `lobby_waiting` -> `ready_confirmed` -> `team_assigned` -> `stage_briefing` -> `stage_playing`
- `stage_playing` -> `investigation_active`
- `investigation_active` -> `stage_playing`
- `stage_playing` -> `solved_spectator`
- `solved_spectator` -> `stage_results`
- `stage_results` -> `stage_briefing` or `game_results`

## 7. 컴포넌트 경계

- `LobbyShell`
- `ReadyPanel`
- `TeamAssignmentBoard`
- `StageHUD`
- `InvestigationDrawer`
- `SpectatorBanner`
- `ScoreCard`
- `PrivacyMask`
- `ChatRail`
- `ResultsSummary`

이 경계는 구현 중 재사용 기준이 되며, UI 상태와 데이터 상태를 섞지 않는다.
