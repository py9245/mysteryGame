# Agent 2 UI Direction

## 목적

이 문서는 `Agent 2 / Gameplay Frontend`가 이번 라운드에서 따라야 하는 시각 방향을 고정한다.

현재 단계의 목표는 단순히 화면을 채우는 것이 아니라, `서비스처럼 보이는 UI`로 끌어올리는 것이다.

---

## 이번 라운드의 디자인 키워드

1. `추리 보드 + 사건 파일 + 제한 시간 압박감`
2. `밝은 배경 위 종이 질감/카드 레이어`
3. `강한 정보 위계`
4. `상태가 먼저 읽히는 레이아웃`

금지:

- 기본적인 회색 박스 나열
- 평면적인 흰 배경 한 장
- 의미 없는 카드 반복
- 상태보다 장식이 먼저 보이는 구성

---

## 톤 앤 매너

- 배경은 `크림/아이보리` 계열을 기본으로 한다.
- 포인트 색은 `다크 그린`, `브라운`, `레드 와인`, `브라스 골드` 축으로 잡는다.
- 대기실과 브리핑은 `사건 파일을 펼쳐놓은 느낌`을 준다.
- 게임플레이는 `타이머 압박`, `조사실 점유 상태`, `내 점수`가 가장 먼저 보여야 한다.
- 결과 화면은 `정리된 수사 보고서`처럼 보여야 한다.

---

## 폰트/타이포그래피 방향

- 기본 UI 텍스트는 읽기 쉬운 sans를 쓰되, 제목/숫자/섹션 헤드는 분위기가 있는 serif 또는 condensed 계열을 쓴다.
- 숫자 정보는 `타이머`, `점수`, `질문 횟수`가 한눈에 보이게 크기 차를 확실히 둔다.
- 정보 라벨과 실제 값의 위계를 분리한다.

---

## 레이아웃 우선순위

### 홈 / 로비

- 방 생성과 준비 흐름이 첫 화면에서 즉시 이해되어야 한다.
- `방 코드`, `현재 인원`, `내 준비 상태`, `시작 가능 여부`를 우선 배치한다.
- 팀 배정 전에도 이미 게임의 세계관이 느껴지도록 헤더/배경을 구성한다.

### 게임플레이

- 상단 또는 좌측 고정 영역에 `스테이지`, `남은 시간`, `내 점수`를 배치한다.
- 메인 본문은 `사건 브리핑/힌트`, `채팅`, `조사실 진입 상태`가 충돌 없이 읽혀야 한다.
- 조사실 점유 여부는 버튼 하나가 아니라 `상태 블록`처럼 강하게 보여준다.

### 조사실/관전/결과

- 조사실은 일반 화면과 확실히 다른 집중 모드처럼 보여야 한다.
- 관전 화면은 `내가 정답 성공 후 빠졌음`이 명확해야 한다.
- 결과 화면은 순위표보다 먼저 `왜 이런 결과가 났는지`를 설명하는 요약이 필요하다.

---

## 구현 원칙

1. mock/sample 데이터 구조는 유지하고, 시각 계층만 먼저 강화해도 된다.
2. CSS 변수부터 정의해서 색/간격/반경/그림자 체계를 통일한다.
3. 공통 shell, panel, stat card, section title 패턴을 먼저 만든다.
4. 로비, gameplay, results 세 구간의 시각 언어는 같되 밀도는 달라야 한다.
5. 모바일은 완전 최적화까지는 아니어도 깨지지 않아야 한다.

---

## 이번 라운드에서 꼭 보여야 하는 것

- `서비스 첫인상`
- `게임 상태가 빨리 읽히는 정보 구조`
- `미스터리 게임다운 분위기`
- `기존 typed flow를 해치지 않는 additive 스타일링`

---

## handoff 기준

- Agent 1에게 새 API 요구가 생기면 `어떤 화면 요소 때문에 필요한지`까지 적어서 요청한다.
- Agent 3의 문구/사건 데이터는 그대로 소비하되, 표현 레이어에서 카드/배지/배너 체계로 재배치한다.
